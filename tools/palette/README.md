# Block category pipeline

The color palette and the block-category map are deliberately separate. Each
palette is generated from the exact client JAR of one Minecraft target, while
`block-categories.json` maps stable namespaced block IDs to reusable English
category IDs and does not contain a Minecraft version. The category map is the
union of all supported targets; it may therefore contain blocks absent from a
particular target palette.

## Files

- `input/block-names-<minecraft-version>.txt` is generated by
  `tools/VanillaPaletteGenerator.java` after full-cube, opacity, and falling
  block filtering. Only genuinely generated inputs are checked in; do not copy
  another version's list as a placeholder.
- `classification/block-categories.txt` is the reviewed, tab-separated source
  mapping. Its format is `block_id<TAB>category,category`.
- `BuildBlockCategories.java` accepts one block-name input per target, builds
  their union, and strictly validates exact classification coverage, IDs,
  category names, duplicates, and ordering before writing JSON.
- `ApplyBlockCategories.java` applies that reusable map to a generated
  version-specific color palette. Every target block must be mapped, while
  mappings for blocks from other versions are allowed.
- `src/main/resources/assets/minesplat/palette/block-categories.json` is the
  version-independent generated mapping that can be intersected with a color
  palette from any Minecraft version after that palette is generated.

## Categories

- `all` — every eligible opaque, non-falling full-cube block.
- `survival` — blocks obtainable as placeable items in ordinary vanilla
  Survival.
- `solid_colors` — plain, color-oriented building blocks such as wool,
  concrete, and terracotta. Strongly patterned variants are excluded.

## Generate target data

Generate colors and the reviewed-name input from the exact target client JAR.
The generator validates the requested version against `version.json` inside
the JAR and writes it into the palette:

```sh
java --class-path "path/to/gson.jar" tools/VanillaPaletteGenerator.java \
  1.21.1 path/to/1.21.1-client.jar \
  build/palette/generated-palette-1.21.1.json \
  tools/palette/input/block-names-1.21.1.txt
```

The supported data layout is:

```text
tools/palette/input/block-names-1.20.1.txt
tools/palette/input/block-names-1.21.1.txt
tools/palette/input/block-names-1.21.11.txt
src/main/resources/assets/minesplat/palette/palette-1.20.1.json
src/main/resources/assets/minesplat/palette/palette-1.21.1.json
src/main/resources/assets/minesplat/palette/palette-1.21.11.json
```

At present only the audited 1.21.1 files exist. A target must not be enabled in
a build until its input and palette have been generated and reviewed.

## Build the category JSON

For the current 1.21.1 data:

```sh
java tools/palette/BuildBlockCategories.java \
  tools/palette/input/block-names-1.21.1.txt \
  tools/palette/classification/block-categories.txt \
  src/main/resources/assets/minesplat/palette/block-categories.json
```

Once all three inputs have been generated, build and validate their union:

```sh
java tools/palette/BuildBlockCategories.java \
  tools/palette/input/block-names-1.20.1.txt \
  tools/palette/classification/block-categories.txt \
  src/main/resources/assets/minesplat/palette/block-categories.json \
  tools/palette/input/block-names-1.21.1.txt \
  tools/palette/input/block-names-1.21.11.txt
```

Existing classifications can be reused for matching IDs. Every new ID must be
explicitly classified before the union can be rebuilt, so silent category
omissions cannot enter a release.

## Apply categories to generated colors

The palette generator writes colors and block states without embedding category
policy. Apply the separately maintained mapping afterwards:

```sh
java -cp "path/to/gson.jar" tools/palette/ApplyBlockCategories.java \
  1.21.1 \
  generated-palette.json \
  src/main/resources/assets/minesplat/palette/block-categories.json \
  src/main/resources/assets/minesplat/palette/palette-1.21.1.json
```
